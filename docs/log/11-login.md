## 조사 — 무엇이 로그인 없음을 전제하는가 (2026-08-28)

**무과금.** 코드를 읽었을 뿐이다.

STATUS §2.1 의 "남용 방지는 서비스 전체 합산이다. 로그인이 없어 사용자별로 나눌 수
없다"를 깨는 작업이라, 그 전제에 기대는 곳을 먼저 전수로 찾았다.

### `grep 로그인` 으로 나온 것은 절반이었다

주석이 명시적으로 말하는 곳은 7군데(`rate_limit`·`allowlist`·`config` 두 줄·
`schema.sql`·`App.tsx`·env 예시 셋)였는데, **정작 중요한 것은 주석에 없었다:**

| 위치 | 그때 동작 |
|---|---|
| `chat.py` `_load_session()` | **UUID 형식만 검사한다. 인가가 한 줄도 없다** |
| `analyze.py` `_start_session()` | 클라이언트가 준 session_id 를 **스냅샷만 맞으면 재사용** |
| `chat_sessions` | 소유자 열이 없다 |
| `summary_cache.build_key()` | `(owner, name, key_source, version)` — 사용자 차원이 없다 |
| `index_queue` | 큐 튜플에 토큰이 없다 |

**즉 세션 UUID 가 곧 권한이었다.** 추측할 수 없는 값이라 사고가 나지는 않았지만,
"가진 사람이 주인" 이라는 것이 설계였다. 로그인을 붙이면서 여기에 답하지 않으면
**로그인은 화면 장식이고 접근 통제는 그대로 없다.**

### 설계를 가른 사실 둘

**① 배경 색인이 토큰 저장을 강제한다.** `indexer.run_build` 는 큐 워커 스레드에서
`fetch_source_files()` 로 GitHub 을 **다시** 부른다 — 요청이 끝난 뒤다. 그래서
"요청 동안만 메모리에 들고 있는다"가 이 구조에서는 성립하지 않고, 사용자 토큰으로
private 저장소를 읽으려면 **보관 말고는 길이 없다.**

**② 캐시·스냅샷·보관 소스가 전부 전역이다.** private 을 받는 순간 B 가 같은
`owner/name` 을 넣으면 A 의 요약이 캐시에서 나온다.

둘 때문에 **scope 결정이 곧 저장·격리 설계의 크기를 정한다.** 그래서 이번 범위는
`scope` 없음 + 토큰 미저장 + private 미지원으로 닫았다.

## 구현 — 꺼짐이 기본인 로그인 (2026-08-28)

브랜치 `feat/oauth`. **무과금** — LLM 을 부르지 않고, GitHub 도 테스트에서는 대역이다.

### 채택한 설계

| 축 | 정한 것 | 이유 |
|---|---|---|
| 세션 | **HttpOnly 쿠키 + DB(`logins`)** | 로그아웃이 즉시 유효하다(행을 지운다). 서명키가 안 는다 |
| 토큰 | **저장하지 않는다** | `GET /user` 한 번에 쓰고 버린다. 비밀값이 안 는다 |
| scope | **요청하지 않는다** | 스코프 없는 토큰으로도 공개 프로필이 온다. 인가 화면에 "public data only" |
| 상한 | **층을 하나 더한다** | `DAILY_*` 는 비용 천장이라 합산으로 남고, 사용자 층이 그 아래 |

**표 이름을 `logins` 로 뒀다.** `sessions` 로 두면 이 저장소에서 "세션"이 두 개념이
된다 — 대화 한 건(`chat_sessions`)이 이미 그 낱말을 쓰고 있다.

### 꺼짐이 기본이다 — 그리고 그것이 이 작업의 안전장치다

`GITHUB_OAUTH_CLIENT_ID` 가 비면 `/auth/*` 가 404 이고 `login_session.current_user`
가 **쿠키를 아예 보지 않는다.** `ALLOWED_REPOS` 가 비면 허용 목록이 꺼지는 것과 같은
관용구다.

**배포는 이 값을 비워 둔 채로 간다.** OAuth App 은 콜백의 host·port 가 정확히 일치해야
하는데 인스턴스를 껐다 켤 때마다 퍼블릭 IP 가 바뀐다(09 로그 재기동 절차 1번).
도메인이 생긴 뒤에 켠다. 그때 **운영용 앱을 새로 만든다** — OAuth App 은 콜백 URL 을
하나만 가지므로 로컬 앱을 고쳐 쓰면 개발이 죽고 개발 secret 이 곧 운영 secret 이 된다.

**라우터는 조건부로 include 하지 않는다.** 기동 시점에 판정이 굳으면 테스트가 껐다
켜며 확인할 수 없는데, **꺼진 상태의 동작을 고정하는 것이 이 기능의 유일한 보증**이다.

### 소유자 검사 — 한 곳에 모았다

`_load_session()` 하나다. `/chat` 의 네 경로가 전부 그것을 거친다. 규칙은 둘:

- `user_id` 가 **NULL 이면 누구나** 본다 — 익명 대화이고 **로그인 도입 전과 같다**
- 값이 있으면 **그 사람만** 본다. 다른 사용자도 익명도 **404**(403 이 아니다 —
  없는 것과 남의 것을 구분해 줄 이유가 없다)

`_start_session()` 도 같은 규칙으로 재사용을 가른다. 그 자리는 **클라이언트가 보낸
session_id** 를 받으므로, 스냅샷만 보면 남의 대화를 이어 쓸 수 있었다.

**로그인해도 옛 익명 대화를 가져오지 않는다.** 가져오게 하면 세션 id 를 아는 누구나
남의 대화를 자기 계정에 붙일 수 있다.

### 로컬 출처를 하나로 만들었다

`5173 ↔ 8000` 이 다른 출처라 `SameSite=Lax` 쿠키가 안 실린다. CORS 에
`allow_credentials` 를 여는 대신 **Vite proxy** 로 같은 출처를 만들었다 — 그쪽은
실제로 교차 출처 요청을 허용하는 것이라 방어를 내주는 일이고, 배포(nginx 한 출처)와
구조도 달라진다. `main.py` 의 CORS 는 손대지 않았다.

**그래서 `api.ts` 의 `API_BASE` 기본값이 빈 문자열이 됐다.** `/auth` 만이 아니라
`/analyze`·`/chat` 도 프록시를 타야 쿠키가 함께 간다 — 안 그러면 로그인해도
`/chat` 이 익명 요청으로 도착하고, **오류 없이 소유자 검사만 조용히 빗나간다.**

`vite.config.ts` 의 경로 목록은 `nginx.conf` 의 정규식과 같은 집합이어야 한다.
갈리면 로컬에서 되는 것이 배포에서 404 가 되고, 그 404 는 SPA 폴백에 먹혀 200 으로 보인다.

### 실제 스택으로 양쪽을 확인했다 (2026-08-29)

`uvicorn` + `vite dev` + 개발 DB 를 띄우고 **Vite proxy 를 거쳐** 확인했다.
GitHub 인가 화면 앞까지만 간다 — 그 뒤는 남의 서버다.

| | 켜짐 | 꺼짐(`GITHUB_OAUTH_CLIENT_ID=`) |
|---|---|---|
| `/auth/me` | `{"enabled":true,"user":null}` | `{"enabled":false,"user":null}` |
| `/auth/login` | 302 → github.com | **404** |
| `/auth/callback` | — | **404** |
| `/auth/logout` | — | **404** |

`redirect_uri` 가 `http://localhost:5173/auth/callback` 로 나갔다 — **8000 이 아니다.**
프록시를 거쳤으므로 쿠키가 SPA 와 같은 출처에 남는다. 인가 URL 에 `scope` 파라미터가
**없는 것**도 함께 확인했다(client_id·redirect_uri·state 셋뿐).
state 쿠키는 `HttpOnly; Max-Age=600; Path=/; SameSite=lax` 이고 `Secure` 는 없다 —
출처가 http 라 유도 규칙이 의도대로 동작했다.

### 남은 것

- **브라우저에서 화면을 못 봤다.** Chrome 확장이 연결돼 있지 않아 `AuthBar` 가 실제로
  그려지는지(로그인 버튼 · 아바타+이름 줄) 눈으로 확인하지 못했다. HTTP 층은 다 봤지만
  **React 렌더링은 테스트가 없다**
- **GitHub 인가를 완주하지 않았다.** 콜백 이후(코드 교환 → `users.upsert` → 쿠키)는
  대역으로만 검증됐다. 실제 왕복은 사람이 한 번 해 봐야 한다
- **`delete_expired()` 는 `services/cleanup.py` 에 연결했다.** 그냥 두면 이번 변경이
  만든 죽은 코드이고(CLAUDE.md §2·§3), 정리 모듈은 이미 survey/apply 짝이라 자리가
  맞았다. **다른 항목들과 성격은 다르다** — 만료 행은 남아 있어도 틀리지 않는다
  (`get_login` 이 SQL 로 거른다). 쌓이지 않게 하는 것뿐이다
