## STATUS §2 를 코드·실행으로 훑는다 (2026-08-30)

**무과금.** LLM 을 한 번도 부르지 않았다. 저장된 답변을 다시 읽거나 코드를 읽었을 뿐이다.

§2 는 자동으로 잴 수 없는 구역이라 `test_status_doc.py` 가 **경로가 실재하는지만**
본다. 낡음 경고가 켜져 있어서(6f29059 이후 `Back/app/` 이 960줄 바뀌었다) 훑었다.

**문서만 읽고 넘어가지 않았다.** 전례 둘(`_log_stale_indexes()` 를 실제로 돌린 것,
저장소 이름을 전수 grep 한 것)을 그대로 따랐다.

### 어긋난 것 셋 — 코드를 정답으로 두고 문서를 고쳤다

**① §2.1 이 없는 함수를 가리키고 있었다.** 관리자 경로 설명이 `_run_and_log` 를
가리키는데 그 이름은 `Back/` 어디에도 없다. 실제 함수는 `admin.py` 의 `_summarize`
이고, 그 docstring 이 문서와 같은 말을 적어 두었다("둘 다 캐시를 조회하지 않고 항상
LLM을 호출하며, 남용 제한도 걸지 않는다"). **동작 설명은 맞았고 이름만 낡았다.**

왜 안 잡혔는지가 더 중요하다 — `test_narrative_paths_exist()` 의 `DOC_PATH` 는
``Back/`` 로 시작하는 백틱 경로만 뽑는다. 함수 이름만 백틱에 넣으면 검사 밖이다.
그래서 `Back/app/api/admin.py` 를 함께 적는 형태로 고쳤다. **이제 이름이 바뀌면
경로 검사가 파일까지는 잡는다.**

**② §2.1 이 상한 세 층의 순서를 안 적고 있었다.** "일일 상한 아래에 IP, 로그인한
요청에는 사용자별 하나 더" 까지만 적혀 있었는데, `db/rate_limits.py` 의 `reserve()`
는 **IP → 서비스 → 사용자** 순으로 본다. 순서가 곧 동작이다:

- IP 에 막힌 요청은 일일 카운터를 **안 올린다**. IP 검사가 일일 `INSERT` 앞이라
  거절이 트랜잭션을 통째로 되돌린다(`test_rejected_request_does_not_consume_the_daily_count`)
- 사용자 층을 서비스보다 먼저 보면 서비스가 이미 천장에 닿았는데 사용자 카운터만
  올라간다. 코드 주석이 그 이유를 적어 두었고, 문서에는 없었다

**③ §2.4 의 "한 대화 안에서 바뀌지 않는다" 가 절반만 맞았다.** 도구를 안 붙이는
두 경우(전체 주입 / 색인 미완료)를 묶어 "둘 다 한 대화 안에서 안 바뀐다"고 적었는데,
`chat.py` 는 **요청마다** `indexer.is_ready()` 를 다시 본다. 전체 주입 여부는 스냅샷
속성이라 안 바뀌지만, 색인은 대화 도중에 끝날 수 있고 그러면 그 다음 질문부터 도구가
붙는다. 코드 주석은 "한 대화 안에서는 안 바뀐다"를 **전체 주입 쪽에만** 걸어 두었다 —
문서가 그것을 두 경우에 걸쳐 읽은 것이다.

같은 자리에 청크 상한도 반영했다. `skipped` 스냅샷은 `is_ready()` 가 False 라 이
버킷에 들어오는데, "색인이 **아직** 안 끝난" 이라고만 적혀 있으면 기다리면 된다는
뜻으로 읽힌다. 상한을 넘긴 스냅샷은 앞으로도 안 만들어진다.

### 실행으로 확인한 것

**`_log_stale_indexes()` 를 실제로 돌렸다.** §2.2 의 "기동 시 무엇이 낡았는지 로그로만
알린다"가 그대로다 — 경고 7줄이 나오고 큐에는 아무것도 안 들어갔다. 현재 규칙은
`3d1494f9`, 로컬 색인은 전부 `822bb217` 이다.

덤으로 §2.2 의 "작은 저장소는 빌드를 청크 0개로 완료 처리한다"가 실제 행으로 확인됐다 —
스냅샷 #23(apns4j) 이 `full_injection=True · chunks 0 · completed` 다.

**규칙 해시는 STATUS 에 적혀 있지 않다. 그게 맞다.** §1.2 가 "손으로 관리하는 값이
아니다"라고 적고 값을 안 적는다. 적었으면 손으로 관리하는 값이 하나 늘고 조용히 낡는다.
현재 값 `3d1494f9` 는 `12-index-time.md` 의 기록과 같다.

**저장소 이름 전수 grep 히트 0.** `Back/app/` 의 `.py`·`.html`·`.sql` 을
`jjunyuongv|marryday|apns4j|teaey` 로 훑어 0건. §2.3 · CLAUDE.md §7 이 그대로다.

### 기계로 못 잰 것과 그 대신 한 것

**이 셋은 재계산 경로가 없다. 무엇으로 확인했는지 적어 둔다.**

- **도구별 호출 분포 `grep 86 · search_code 83 · read_file 52`** —
  `citation_evals.jsonl` 의 행에는 도구 이름이 안 남는다(`id·kind·cited·answer·토큰·비용`
  뿐). **출처를 거슬러 확인했다** — `07-answer-quality.md:825` 에 같은 세 숫자가 있다.
  숫자를 다시 뽑은 것이 아니라 **출처가 있는지만** 본 것이다
- **EC2 실측(청크당 1.898초 · 300청크 ≈ 9.5분)** — 이 기계에서 잴 수 없다.
  `config.py` 주석과 12 로그의 기록을 대조하는 데서 멈췄다
- **배포 전제(로그인 꺼짐 · admin 이 밖에서 안 닿음 · `--force-recreate`)** —
  인스턴스가 꺼져 있다. 대신 **설정 파일에서 확인했다**: `Front/nginx.conf` 의
  `location ~ ^/(analyze|chat|health|auth)(/|$)` 에 `admin` 이 없고,
  `docker-compose.prod.yml` 이 `TRUST_PROXY_HEADERS: "1"`, nginx 가
  `proxy_set_header X-Forwarded-For $remote_addr` 로 덮는다. **셋이 짝인 것까지는
  파일로 보이지만, 실제로 밖에서 안 닿는지는 인스턴스를 켜야 안다**

### 코드에서 그대로 확인한 것 (문서 수정 없음)

§2.1 단일 프로세스 전제 3종(메모리 큐 · `reset_running()` · `threading.Lock`) ·
DB 장애 시 통과(`except DB_ERRORS: return`) · 캐시 히트에 상한을 안 거는 것(`/analyze`
가 캐시 히트에서 먼저 `return`) · OAuth 가 scope 를 안 넣고 토큰을 안 보관하는 것 ·
`ALLOWED_REPOS` 기본 꺼짐 · §2.2 원문 보관이 **전체 주입 판정보다 앞**이고 상한 초과면
한 행도 안 넣는 것 · §2.4 의 `_file_for_line` 3단계 순서 · `CITATION_CONTEXT_LINES=20` ·
캐시 브레이크포인트 2개 · `tool_choice` 를 안 바꾸고 꼬리에 안내를 붙이는 것 ·
`MAX_TOOL_ROUND_TRIPS=3` · `NO_ANSWER`/`NO_ANSWER_AFTER_TOOLS` 가 `round_trips` 로
갈리는 것 · `runs` 의 `round_trips`·`stop_reason` 열 · `list_messages` 가 읽는 쪽에서
빈 답변을 거르는 것.

**청크 상한이 §2.2 의 색인 생애 서술과 어긋나는 곳은 없었다.** `run_build()` 의 순서가
`원문 보관 → 전체 주입 판정 → 청킹 → 상한 판정 → 임베딩` 이라, 상한을 넘긴 스냅샷도
**원문은 보관된다.** "보관 소스가 있어야 인용이 만들어진다"(§2.4)와도 맞는다.
