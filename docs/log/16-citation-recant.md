## 맞는 인용을 모델이 철회한 표본 · 링크 0건 조사 (2026-09-01)

**조사만 했다. 코드는 한 줄도 안 고쳤다.** LLM 을 부르지 않았다 — 전부 로컬 DB 와 임베딩 검색으로 재현했다.

### 들어온 표본과 전제

사용자 화면에서 두 문제가 보였다. (1) 모델이 "검색 도구로 확인했다"며 행 번호를 적었다가 다음 턴에
"요약·추정으로 만들어낸 값"이라고 사과했다. (2) `파일명` + 행 번호 형식이 여럿인데 근거 링크가
하나도 안 걸렸다. 전제는 "청크 상한(300)을 넘어 색인이 SKIPPED 된 저장소" 였다.

**전제 셋이 실측과 어긋났고, 결론은 그 위에 선다.**

| 전제 | 실측 |
|---|---|
| 색인이 SKIPPED 된 스냅샷 | **`completed`.** 로컬 스냅샷 12(Marryday)는 활성 빌드 96(4,365청크, 08-19)이 살아 있다. 상한(08-29 도입)보다 먼저 만든 색인이라 그대로다. 화면은 completed 면 배너를 안 그린다 |
| 행 번호를 지어냈고 사과가 사실 | **행 번호는 전부 맞고, 사과가 틀렸다.** 인용 범위 8개가 빌드 96 의 실제 청크 경계와 1:1 로 일치한다 |
| `read_file` 한 건은 실제 확인 | **`read_file` 은 붙은 적이 없다.** 보관 소스 0개라 `search_code` 만 붙었다(`tools.build`). 332-354 는 08-21 턴의 검색 결과다 |

### 조사 1 — 그 대화

로컬 DB 다(EC2 가 아니다). 세션 `bbe79236-92e2-4fcc-ad21-1025ca25a2b7`, 스냅샷 12, 익명.
표본은 메시지 #69~#74, `runs` 78~80 (12:17~12:19 UTC).

| 메시지 | run | round_trips | 내용 |
|---|---|---|---|
| #70 답변 | 78 | **1** | `routers/body_analysis.py` 332-354 · `services/body_analysis_service.py` 147-169 · `body_analysis.py` 423-440 · 440행 |
| #72 사과 | 79 | **0** | "실제 도구로 확인한 것이 아니라 만들어낸 값" — **도구를 안 부르고** 철회 |
| #74 재확인 | 80 | **1** | 147-169 · 407-425 · 423-440 · 489-504 · 208-224 — #70 과 같은 값이 다시 나옴 |

도구 구성은 `chat.py` 가 `indexer.is_ready` → `index_status.is_completed` → active_build_id 96 으로
True 를 받아 `tools.build(12)` 를 불렀고, `snapshot_source_files` 가 0행이라 `SEARCH_ONLY_SCHEMAS`
(search_code 하나)를 줬다. 색인이 소스 보관 기능보다 먼저 만들어진 옛 스냅샷이다.

**진짜 SKIPPED 라면 도구는 0개다.** `index_status.skip()` 은 활성 포인터를 안 건드리고 첫 색인은
포인터가 없으므로 `is_ready` False → `tools=None`. `test_a_skipped_build_is_not_ready_and_gets_no_tools`
가 이미 고정한다. 예외는 재색인이 skipped 로 끝난 경우 — 옛 활성 빌드가 남아 도구가 그대로 붙는다.

**행 번호가 진짜라는 증거** (무과금):
- `code_chunks_1024_int8 WHERE build_id=96` 에 (332,354)·(147,169)·(423,440)·(407,425)·(489,504)·(208,224)
  ·(166,181)·(455,476) 청크가 전부 있다
- `indexer.search_code(12, "체형 분석 구현은 어떻게 한거야?")` 상위 8 에 332-354(4위)·407-425(7위)가 든다
- 같은 저장소의 보관 소스(스냅샷 17, 181파일)와 대조 — 147-169 는 `calculate_measurements` 정의,
  423-440 은 Gemini 우선/랜드마크 폴백 분기, 440 은 `if height and weight:`. 서술까지 맞다

**왜 틀린 사과가 나왔나.** `tool_result` 는 이력에 저장하지 않는다(STATUS §2.4). 그래서 #72 턴의
모델은 #70 의 본문은 보지만 **그 숫자가 어디서 왔는지는 못 본다.** "근거로 몇행인지 안알려줘?" 라는
애매한 질문을 추궁으로 읽고, 근거가 안 보이는 숫자를 지어낸 것으로 철회했다. 프롬프트의
"행 번호는 주어진 것만 쓰세요"가 그 방향을 민다. 08-21 의 #38 도 같은 모양이었다 — "이전 답변의
566-595행·270-300행은 요약 정보에 근거한 것"이라며 철회.

### 조사 2 — 링크가 왜 안 걸렸나

`citations` 파서를 답변 원문에 그대로 돌렸다.

| 답변 | `extract()` | `for_answer(paths=[])` — 실제 | `for_answer(스냅샷 17 경로)` — 가정 |
|---|---|---|---|
| #70 | 4건 | **0건 · 경로 해석 실패 4** | 4건 전부 링크 |
| #72 | 1건 (파일명 없음 2 — 사과문의 "(147-169행, 423-440행 등)") | 0건 · 경로 해석 실패 1 | 1건 |
| #74 | 5건 | **0건 · 경로 해석 실패 5** | 5건 전부 링크 |

추출은 다 됐고 경로 형식도 문제가 아니다 — 보관 경로가 `final-repo-back-main/services/…` 여도
`_matching_paths` 가 `endswith("/" + name)` 이라 `services/x.py` 로 풀린다. **원인은 하나, 보관
소스가 0개라 `_stored_paths()` 가 빈 목록.** STATUS §2.4 의 설계 그대로인데, 카운터가 그것을
"경로 해석 실패"로 세어 §2.4 의 "경로 해석 실패는 0이다"와 이름이 부딪힌다.

**부수 발견.** `run_build` 는 `_store_sources` 를 상한 판정보다 먼저 부른다. 스냅샷 12 를 재색인하면
소스 2.4MB(<20MB)가 보관된 뒤 4,365 > 300 으로 skipped 가 되고, `skip()` 은 포인터를 안 건드리므로
검색은 옛 빌드 96 그대로에 `read_file`·`grep`·링크가 붙는다. 같은 이유로 진짜 SKIPPED 스냅샷도
소스는 남아 링크는 걸린다. 문서에 없던 성질이라 STATUS §4 에 적었다.

### 조사 3 — 인용의 유형

F(파일 단서 없음)·D(심볼만) 둘 다 아니다 — 9건 전부 파일+범위가 같은 줄에 있다. "형식은 맞는데
값이 거짓"도 아니다 — 값이 참이다. 새 유형은 **"형식·값 다 맞는데 모델이 스스로 거짓이라고
철회"** 다. 지금 자(인용 정확도·거절 채점기) 어느 것도 이것을 안 잰다.

가상의 "값이 거짓" 유형을 지금 자가 잡는가 — 줄에 `CODE_LIKE` 조각이 있을 때만이다. 이 표본을
`tests/test_line_accuracy._verdict` 에 넣으면 #70 은 4건 중 1건만 채점(423-440,
`classify_body_type(measurements)` 로 correct), #74 는 5건 전부 `off`. 값이 거짓이었어도 9건 중
1건만 잡혔을 것이다.

### 선택지 — 결정은 남아 있다

| 안 | 하는 일 | 파급 | 잡히는 것 |
|---|---|---|---|
| 가. 유실 사유 가르기 | `citations.for_answer` 에서 `paths` 가 비면 "보관 소스 없음"으로 센다 | 코드 몇 줄, 테스트 1개 | 링크 0건의 원인이 로그에 보인다. §2.4 진술이 다시 참이 된다 |
| 나. 옛 스냅샷 소스 채우기 | 스냅샷 12 재색인(부수 효과로 소스 보관 → skipped) 또는 "소스만 보관" 관리자 동작 | 전자는 코드 0줄·tarball 1회, 빌드 목록에 skipped 행이 남는다 | 이 저장소의 링크·read_file·grep. 데이터 정리다 |
| 다. 철회 방지 — 프롬프트 | "앞 턴의 인용은 그때 도구로 확인한 것일 수 있다. 출처가 안 보인다고 철회하지 말고 다시 확인하라" 한 줄 | 캐시 접두사 1회 갱신. 효과를 잴 자가 없다(표본 2건) | 틀린 사과 |
| 라. 철회 방지 — 출처 남기기 | 답변 저장 시 "(근거: search_code N회)" 같은 꼬리를 본문에 붙여 다음 턴이 보게 | 이력 토큰 소폭 증가, 화면 표시 규칙 필요 | 다와 같되 구조로 막는다 |
| 마. 화면에 도구 범위 표시 | `/chat/{id}/index` 에 `has_sources` 를 실어 "검색만 되고 원문·링크는 안 됨" 배너 | 스키마 1필드, 배너 1개 | 이번 오인 |
| 바. 기록만 | STATUS §4 에 표본 기록 | 0 | — |

**권장은 가 + 바 지금, 다는 표본이 쌓이면.** 나는 STATUS §4 가 marryday 재색인을 미루기로 한 결정과
부딪히므로 따로 판단. 다·라는 표본 2건으로 상수를 움직이는 패턴이다. **이번에 한 것은 바뿐이다.**

### 함정 — 이번에 밟은 것

- **모델의 사과를 사실로 받았다.** "지어냈다"는 말이 곧 지어냈다는 증거가 아니다 — 모델은 자기 앞
  턴의 출처를 못 보므로 참인 인용도 철회한다. 확인 순서는 `runs.round_trips` → 청크 경계 대조다.
- **"4,365 > 300 이니 SKIPPED" 로 추정했다.** 상태는 `index_builds`·`snapshot_index_status` 가 답하고,
  상한은 새 색인에만 걸린다. 화면 배너가 없는 것이 곧 "정상"이 아니다 — 보관 소스 0개인 옛 색인은
  배너 없이 검색만 된다.
